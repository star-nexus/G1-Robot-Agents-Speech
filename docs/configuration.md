# Configuration model

The project uses two configuration layers with non-overlapping ownership.

| Layer | File | Owns |
|---|---|---|
| Model profile | `config*.json` | ASR backend, checkpoint, device, dtype, attention, cache, model prompt |
| Host deployment | `deploy.env` | Selected profile path, Python/runtime libraries, microphone, shared VAD/playback behavior, transport, installer |

The separation is intentional: changing a host setting must never silently replace
the ASR model, while changing an ASR model must not require new DDS/ROS 2 units or
downstream Agent code.

## Files in the project root

Community-visible templates:

- `config.example.json`: canonical full schema and defaults; defaults to SenseVoice.
- `config.qwen3-asr.example.json`: one portable Qwen3-ASR model profile.
- `deploy.env.example`: complete host-deployment schema with neutral values.

Host-local generated files are ignored by Git:

- `config.json`: CPU SenseVoice profile generated by `setup-cpu.sh`.
- `config.gpu.json`: GPU SenseVoice profile generated by `setup-jetson-gpu.sh`.
- `config.qwen3-asr.local.json`: the selected Qwen3-ASR profile for this host.
- `deploy.env`: the selected profiles and host/runtime settings.

Do not keep benchmark variants as additional root-level `config.qwen3-*` files.
Record their settings in the corresponding benchmark JSON instead.

## Ownership and precedence

Service startup resolves configuration in this order:

1. Canonical dataclass defaults fill fields omitted by an intentionally small JSON.
2. The JSON profile selects the ASR backend and every model-specific value.
3. Backend-neutral variables from `deploy.env` override audio, VAD, DDS/ROS 2, and
   playback-gate fields.
4. The service selector's explicit `dds|ros2` argument chooses the active transport.

`deploy.env` cannot override these model-profile fields:

```text
asr.backend
sensevoice.*
qwen3_asr.*
```

Consequently, `ASR_BACKEND`, `SENSEVOICE_*`, and `QWEN3_ASR_*` are not deployment
variables. Use JSON or an explicit `g1-speech config init --set ...` command when
creating a model profile.

## Switching models

SenseVoice GPU uses the standard Jetson GPU environment:

```bash
# deploy.env
SPEECH_CONFIG_GPU="config.gpu.json"
SPEECH_PYTHON_GPU=""
SPEECH_GPU_LIBRARY_PATH=""

sudo g1-speech-service restart
```

Qwen3-ASR selects its JSON and, when needed, an isolated compiled runtime:

```bash
# deploy.env
SPEECH_CONFIG_GPU="config.qwen3-asr.local.json"
SPEECH_PYTHON_GPU="/absolute/path/to/qwen-runtime/bin/python"
SPEECH_GPU_LIBRARY_PATH="/optional/native/library/directory"

sudo g1-speech-service restart
```

If no service is selected, start one explicitly:

```bash
sudo g1-speech-service gpu dds
# or: sudo g1-speech-service gpu ros2
```

The systemd unit, microphone pipeline, event contract, DDS/ROS 2 topics, and Agent
subscribers remain unchanged.

## Shared pipeline settings

The following `deploy.env` groups are deliberately shared by every ASR backend:

- `AUDIO_INPUT_*`: backend, callback block, latency request, and fallback policy.
- `ALSA_INPUT_*`: stable physical card ID and native hardware capture format.
- `PULSE_INPUT_DEVICE`, `PULSE_SOURCE`: PulseAudio fallback device and optional
  pinned source.
- `VAD_*`: utterance start/end segmentation before ASR inference.
- `PLAYBACK_*`: recognition suppression while the robot is speaking.
- `DDS_*`, `SPEECH_TOPIC`, `PLAYBACK_TOPIC`: DDS discovery and reliability.
- `ROS2_*`: ROS 2 discovery, topics, and QoS.

For example, `VAD_MIN_SILENCE_SECONDS=0.2` means the same 200 ms end-of-utterance
policy for SenseVoice and Qwen3-ASR. It is not a model-specific tuning value.

Backend-neutral values are applied both by `config init --from-env` during setup and
again by the service at startup. Edit `deploy.env`, then restart the selected service.
The complete Jetson input design and verification procedure is documented in
[`audio_input.md`](audio_input.md).

## Creating the one local Qwen profile

```bash
cp config.qwen3-asr.example.json config.qwen3-asr.local.json
```

Edit `model_dir` and any model-specific options in that JSON. Validate before
selecting it:

```bash
.venv-gpu/bin/g1-speech doctor \
  --config config.qwen3-asr.local.json --load-model --skip-audio
```

Platform-specific optimized runtimes may use the same JSON filename while changing
its cache/compile fields based on measured evidence. Keep those host-specific values
out of the community template.
